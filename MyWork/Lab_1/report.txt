Короткий виклад вимог:

Завдання:
Є відеохостинг-платформа (аналог YouTube). Потрібно спроектувати базу даних,
яка зберігатиме інформацію про користувачів, відео, коментарі, лайки та підписки.

Потреби зацікавлених сторін:
Платформа повинна зберігати інформацію про користувачів (їні профілі),
відео (з метаданими), коментарі до відео, лайки користувачів на відео,
та підписки користувачів на інших користувачів (канали).
Система повинна підтримувати додавання, редагування та видалення контенту.

Бізнес правила та дані для зберігання:
- Кожен користувач має унікальний email та username.
- Користувач може авторизуватись через Google (googleId) або за паролем.
- Кожен користувач має аватар, банер та опис каналу (необов'язково).
- Кожне відео має назву, опис (необов'язково), URL файлу, мініатюру (thumbnail).
- Відео має лічильник переглядів (за замовчуванням 0).
- Відео належить одному користувачу (автору).
- Користувач може залишати коментарі до відео.
- Коментар містить текст та дату створення.
- Користувач може поставити лайк на відео (один лайк на відео від одного користувача).
- Користувач може підписатись на іншого користувача (канал).
- Підписка унікальна: один користувач може підписатись на іншого лише один раз.
- Кожен запис має дату створення (createdAt).

Список сутностей з їх атрибутами:

User {
  id: PK (UUID),
  email: UNIQUE, NOT NULL,
  username: UNIQUE, NOT NULL,
  password: NULLABLE,
  google_id: UNIQUE, NULLABLE,
  avatar: NULLABLE,
  banner: NULLABLE,
  description: NULLABLE,
  created_at: NOT NULL
}

Video {
  id: PK (UUID),
  title: NOT NULL,
  description: NULLABLE,
  url: NOT NULL,
  thumbnail: NULLABLE,
  views: DEFAULT 0,
  created_at: NOT NULL,
  author_id: FK -> User(id)
}

Comment {
  id: PK (UUID),
  text: NOT NULL,
  created_at: NOT NULL,
  user_id: FK -> User(id),
  video_id: FK -> Video(id)
}

Like {
  id: PK (UUID),
  user_id: FK -> User(id),
  video_id: FK -> Video(id),
  UNIQUE(user_id, video_id)
}

Subscription {
  id: PK (UUID),
  subscriber_id: FK -> User(id),
  channel_id: FK -> User(id),
  created_at: NOT NULL,
  UNIQUE(subscriber_id, channel_id)
}


Пояснення зв'язків прозою:

- User – Video: один до багатьох. Один користувач (автор) може завантажити багато відео,
  але кожне відео належить лише одному автору. Зв'язок через author_id (FK).

- User – Comment – Video: один до багатьох з обох сторін.
  Один користувач може залишити багато коментарів, і одне відео може мати багато коментарів.
  Коментар належить одному користувачу та одному відео.

- User – Like – Video: один до багатьох з обох сторін.
  Один користувач може поставити лайки на багато відео, і одне відео може мати багато лайків.
  Обмеження: один користувач = один лайк на відео (UNIQUE).

- User – Subscription – User: багато до багатьох (самореференсний зв'язок).
  Один користувач (subscriber) може підписатись на багато каналів,
  і один канал може мати багато підписників.
  Обмеження: один підписник = одна підписка на канал (UNIQUE).
  Користувач не може підписатись сам на себе.


Припущення та обмеження:

- Пароль може бути NULL, якщо користувач авторизується лише через Google.
- google_id унікальний і може бути NULL для користувачів з паролем.
- Лічильник переглядів збільшується при кожному перегляді відео.
- Видалення відео каскадно видаляє його коментарі та лайки.
- Видалення користувача каскадно видаляє його відео, коментарі, лайки та підписки.
- URL відео зберігає посилання на файл у сховищі (S3/CDN), сама БД не зберігає файли.
- Дата створення (created_at) встановлюється автоматично при вставці запису.
- Email та username унікальні по всій системі.
